# Contributing

Discuss substantial changes in a GitHub issue. Include the user problem, expected outcome and supported environment; never attach credentials or private customer evidence.

Use Python 3.12 and `uv sync --locked --group dev`. Keep changes focused, update docs and preserve the owned-fixture execution boundary. Providers must enforce budgets and never turn infrastructure failures into UX abandonment.

Finish construction before a consolidated acceptance batch. Rerun failed checks and directly affected integrations only. Prefer disposable GitHub Actions for browser-heavy gates. Run Ruff and check the patch before submission.

PRs should describe behavior, validation and limitations. Project contributions use MIT; dependencies, datasets and models keep their licenses.
