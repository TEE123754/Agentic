# Phase 3 remote isolation gate

The manual [GitHub Actions workflow](../.github/workflows/phase3-isolation.yml) runs on a disposable Ubuntu runner in the private `TEE123754/Agentic` repository. It does not install WSL, Podman, Chrome, or model weights on the user's laptop. The workflow has no website URL input and runs only the bundled, synthetic storefront fixture. Browser policy and the owned sentinel still verify that the fixture never reaches a deployed product.

The runner installs dependencies from `uv.lock`, builds the small code worker from a base image recorded by GHCR digest, and captures the worker image SHA-256 ID. It requires rootless Podman. One boundary batch checks network isolation, host file/credential/socket access, process/memory/CPU/wall-time/output limits, unapproved code, stale or forged broker actions, cleanup, and an unchanged host sentinel. A passing record is bound to that runner and image ID. It cannot be copied to authorize code execution on a laptop or another machine.

Only after the boundary passes does the runner download checksum-pinned open-source llama.cpp and Qwen3-4B resources, run one enterprise evaluator against the owned healthy fixture, and export JSON, Markdown, and offline HTML reports. The final review reads those saved files only; it does not reopen the browser. A model/agent failure remains a failed Phase 3 gate with a retained terminal report. The workflow uploads synthetic run evidence for seven days, including failed checks. No model weights or API tokens are uploaded.

Run the workflow manually from the repository's **Actions → Phase 3 owned-fixture isolation gate → Run workflow** page. Inspect `worker-boundary-review.md`, `code-journey-review.md`, and the terminal `report.html` in the workflow artifact. A passing GitHub runner gate proves the generated-code path for that one runner and owned fixture; it does not enable arbitrary external staging sites, prove human usability, or change the local laptop's isolation status.
