# Phase 3 — One autonomous persona

The runner uses local Qwen3-4B Q4_K_M weights through the checksum-verified llama.cpp runtime. smolagents 1.26.0 provides `Model`, `Tool`, and `ToolCallingAgent`. Playwright and browser-use ground the same browser target. Pydantic and the trusted broker validate every tool call. No API key, cloud inference, credit card, model download, or production URL is needed during execution.

```powershell
& '.venv\Scripts\python.exe' -m frictionlab autonomous --persona impatient_mobile --journey checkout_review
& '.venv\Scripts\python.exe' -m frictionlab autonomous --persona keyboard_low_vision --journey keyboard_checkout
& '.venv\Scripts\python.exe' -m frictionlab autonomous --persona enterprise_evaluator --journey delivery_information
```

Each command creates a fresh owned fixture, proxy, sentinel, synthetic account, and Chrome profile. A local model process chooses each action without a scripted click sequence. The keyboard profile cannot click or tap; activation keys are offered only for a grounded focused control, and typing only for an applicable textbox. Typing accepts declared references, never raw credentials. The trusted runtime checks journey assertions after every action and ends the agent immediately when they pass. An explicit `finish` also requires independent verification. The cohort API remains disabled pending Phase 5.

The host has neither Podman/Docker nor installed WSL. `--mode isolated_code` produces a blocked report before browser/model startup because no matching host/image boundary acceptance record exists. A `CodeAgent` adapter and OCI worker now exist in source, but no generated Python has executed and no local Python executor, dynamic import, shell, Hub tool loading, or arbitrary URL tool is exposed to a running persona. This follows [smolagents' security guidance](https://github.com/huggingface/smolagents): its local executor is not a security sandbox. Real container acceptance remains an unmet gate; the fixture proxy is not an OS sandbox. See the [worker checkpoint](phase3-code-worker.md).

`configs/agent.json` fixes defaults to 24 decisions, 24 tool calls, 240 seconds, 60 seconds/request, 2,800 input tokens, 256 output tokens, 10,000 memory characters, six recent actions, zero provider retries, and no vision. The environment's stricter browser/network limits also apply. Profile retry limits stop repeated ineffective actions as agent-limit outcomes, not churn. Inference startup and model latency are separated from application response time. Memory sampling can terminate the owned model over 8 GiB RSS; this is a sampled process limit, not a kernel memory guarantee. The native prompt cache is capped at 512 MiB rather than its [8,192 MiB default](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md). Its environment excludes credentials and runtime agent/tool overrides; built-in native agent tools, web UI, and MCP proxy are disabled.

The runtime binds an ephemeral numeric loopback port, disables proxy/environment credential discovery, disallows redirects, and accepts only owned local inference. The adapter checks formatted token counts with llama.cpp's [template/token endpoints](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md), then constrains output to a fresh action schema. A process may be reused sequentially across sessions, while every persona receives new memory, tools, and browser state. The runner never reuses a remote endpoint from a user's environment.

Profiles receive bounded viewport-visible text/control names, or accessible semantic content and current keyboard focus. Memory preserves up to four excerpts of previously perceived information and six recent actions with control names. Keyboard historical notes retain paragraph facts without old control/dialog markup; successful keyboard transitions are remembered in the same state, while ineffective interactions remain retryable. Escape is offered only for a currently accessible dialog. These are planning aids, not UX diagnoses. Model scroll increments are limited to 200, 400, or 600 CSS pixels; actual viewport movement is recorded as progress even when the full document text is unchanged. Raw DOM, input values, network bodies, cookies, browser handles, evidence paths, and fixture control operations remain outside model memory. Reading budgets limit text; they do not simulate actual human cognition. Optional visual reasoning is explicitly unavailable in this gate.

Every terminal outcome exports `report.json`, `report.md`, and offline `report.html` under `artifacts/phase3/runs/<UUID>/`. Reports include scope/version/hash/seed, protection and sentinel results, independent completion, action/application/model timing, masked screenshots, all bounded model decisions and rationales, stop category, recommendations, and evidence review. Detailed records are saved in `evidence/planner-memory.json`, `planner-decisions.json`, `planner-review.json`, plus Phase 2 observation/action/network artifacts. Invalid configurations, disabled profile/journey selections, and unsupported agent settings produce a preflight report before any browser/model starts, without echoing rejected values. Review reads saved files only. Reports remain partial: cognitive detectors, abandonment diagnoses, cohorts, heatmaps, remediation findings, and dashboard are later phases.

Construction preceded one consolidated acceptance batch. The declared first seeded healthy threshold was 3/3 and initially failed 0/3. Targeted repairs now give each of the three profiles an independently verified completion, with all 100 distinct checks passing. Ten real healthy attempts across successive implementation versions produced three completions; failures remain recorded. Negative checks cover malformed output, unknown/multiple tools, stale IDs, prompt injection, early finish, token/tool/step/runtime/retry ceilings, cancellation, missing resources, generated-code rejection, preflight/terminal exports, and cleanup. Passing healthy browser/model executions were not repeated; mobile's harness correction used saved evidence only. See the [acceptance record](phase3-validation.md). Full Phase 3 remains partial until the generated-code/container boundary is built and validated.
