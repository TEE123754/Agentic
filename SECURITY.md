# Security reporting

Do not post keys, private audit bundles or exploit details in public issues. Use GitHub private vulnerability reporting if enabled. Otherwise request a private reporting channel from the maintainer without sensitive details. No monitored security email or response SLA is promised.

Only disposable owned fixtures are supported. A staging hostname does not prove isolation; browser interception does not replace a network/data boundary.

Reports are local by default. Inspect exported prose and screenshots before sharing: text redaction cannot prove arbitrary personal information was removed from pixels. Never put credentials in static pages or public Spaces.
